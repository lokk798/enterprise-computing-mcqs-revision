# Enterprise Security MCQ - OAuth2, OpenID Connect & Keycloak

## Question 1

In the CERN badge example from the lecture, what is the primary security benefit of using an authorization code instead of directly providing an access token through the redirect channel?

- a) The authorization code has a longer expiration time than access tokens
- b) The redirect channel is considered untrustworthy, so using a temporary code prevents token leakage
- c) Authorization codes are easier to revoke than access tokens
- d) The authorization code allows for better user experience with fewer redirects
- e) Authorization codes can carry more information than access tokens

**Correct Answer: b**
**Explanation:** The redirect channel (like a phone call redirection) is not considered trustworthy. Using a temporary authorization code that must be exchanged through a secure channel prevents potential token interception during the redirect process.

## Question 2

Which OAuth2 grant types would be most appropriate for a Single Page Application (SPA) that cannot securely store client secrets? (Multiple correct answers)

- a) Client Credentials Grant Type
- b) Authorization Code Grant with PKCE
- c) Resource Owner Password Credentials Grant
- d) Implicit Grant (though deprecated)
- e) Device Authorization Flow

**Correct Answers: b, d**
**Explanation:** SPAs cannot securely store client secrets. Authorization Code Grant with PKCE is the recommended modern approach, while Implicit Grant was previously used but is now deprecated due to security concerns. Client Credentials requires secrets, and Resource Owner Password requires handling user credentials directly.

## Question 6

## Question 11

When implementing refresh token rotation as mentioned in the lecture, what security benefit does this provide?

- a) It reduces the computational overhead of token validation
- b) It allows for longer-lived access tokens without security compromise
- c) It limits the impact of refresh token compromise by invalidating old tokens
- d) It enables cross-domain token sharing between different applications
- e) It simplifies token storage requirements on the client side

## Question 19

What is the security implication of OAuth2 not defining a specific format for access tokens?

- a) It makes token validation inconsistent across different implementations
- b) It allows flexibility but requires coordination between authorization and resource servers for token verification
- c) It prevents standardization of security measures across platforms
